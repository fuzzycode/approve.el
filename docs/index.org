#+title: Approve — documentation map

Approve is an Emacs package for reviewing GitHub pull requests: find them, read
them, comment on code, and submit reviews, all without leaving Emacs.

These documents are the plan we work from.  They are written for humans and
for the AI agents that do most of the coding: each file covers one topic, so a
task only needs the files it touches.

* How to keep these docs true
- A decision that changes gets a new entry in [[file:decisions.org][decisions.org]] that supersedes
  the old one.  Don't silently edit the old one.
- When code and docs disagree, the code is what runs, but the docs say what we
  meant.  Fix whichever is wrong in the same commit.
- Mockups show intent, not pixels.  When the real UI settles, update the
  mockup to match it.
- Flowcharts and diagrams are plain Unicode/ASCII in =#+begin_example= blocks
  ([[file:decisions.org::*D21 Docs in org; diagrams in plain Unicode/ASCII][D21]]).  Lines inside blocks never start with =*= or =#+=, so org
  doesn't parse them.
- The HTML views in =html/= illustrate [[file:ui.org][ui.org]] and [[file:flows.org][flows.org]].  When a mockup or
  flow changes, change its HTML view in the same commit (=make docs= rebuilds
  the diagrams).  Open =html/index.html= in a browser.

* Glossary
- PR buffer :: The buffer that shows one pull request (=approve-pr-mode=).
- Diff buffer :: The optional separate buffer that holds the diff when the
  split layout is chosen ([[file:decisions.org::*D05 One PR buffer by default; split layout optional][D05]]).
- Pending review :: A review the viewer has started on GitHub but not submitted.
  Its comments are visible only to the viewer.  GitHub allows one per user per PR.
- Thread :: A review thread: one or more comments on a line, a range of lines,
  or a file.  It can be resolved and can become outdated.
- Conversation comment :: A comment on the PR itself (GraphQL =IssueComment=),
  not attached to code.
- Context :: What is at point (a diff line, a region, a thread, a comment, a
  file, a label…), resolved by =approve-context-at-point=.  Every DWIM command
  dispatches on it.
- Store :: The buffer-local normalized data store ([[file:architecture.org::*Data model][architecture]]).
- Viewer :: The GitHub user running Approve.
