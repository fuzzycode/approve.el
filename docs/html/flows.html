How the pieces talk architecture.org › Layers

Code depends downwards only. Renderers are pure (store in, text out); only approve-api talks to ghub; callbacks run in the buffer that made the request.

F00 The action pipeline every write · Phase 2

Each command supplies only its checks, its input prompt and its mutation, which patches the store with GitHub's answer and makes the list edits (D35). Nothing changes on screen until GitHub confirms (D14); mutations run one at a time (D15).

F01 Find and open a PR Phases 1, 3 and 9

All ways in end in the same parser. An existing buffer is reused without reloading.

F02 Load a PR Phase 1

Several smaller queries in parallel instead of one big one: the header shows quickly, each section fills in when its data arrives, and one failure only marks its own section.

F20 Look up details K · eldoc · D27 · Phase 1

One line in the echo area as point rests on a thing; everything in the eldoc buffer with K. Moving point never touches the network: missing details are fetched only when wanted.

F21 Review feedback in a file you edit approve-feedback-mode · D45 · D46 · Phase 7

In a clone with the PR's branch checked out, the PR's threads in your own buffer, folded, with a bubble in the right margin. A diff of GitHub's file against the buffer's text places them whatever the clone's state; between diffs the overlays move with the text. One store per PR, held by its PR buffer, which the mode opens unseen when the PR is not open. Mockups: Your clone.

F22 Find a buffer's PR, and a PR's clone P · f (evil: gF) · D45 · Phase 7

A branch, not a clone, has the PR: the head repository's ref finds it, a fork's too. A clone is found by its remotes among approve-clone-directories; one git for-each-ref then says which worktree has the branch.

F23 Commit a suggestion, or a batch of them x · b · D41 · Phase 5

As GitHub's "Commit suggestion" and "Add suggestion to batch", without a clone: the files at the head the buffer has, the suggested lines spliced in, one commit, then the threads resolved and the PR loaded again. With a batch, x commits the batch wherever point is.
